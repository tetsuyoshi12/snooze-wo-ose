# NFR 要件計画

## 目的
非機能要件を明確化し、技術スタックを決定する。

**軽量化方針**: `aidlc-docs/inception/requirements/requirements.md` の「2. 非機能要件」に記載済みの内容を最大限再利用し、実装のために追加で必要な事項のみを定義する。

## 前提条件
- アプリケーション設計が完了している
- 実行計画で NFR 要件ステージの実行が指示されている

---

## ステップバイステップ実行

### ステップ 1: 既存 NFR の確認
- [x] `aidlc-docs/inception/requirements/requirements.md` の「2. 非機能要件」を読み込む
- [x] 既に定義されている NFR を確認：
  - パフォーマンス（AI 5 秒、アラーム 1 秒、UI 1 秒）
  - コスト（$1 以下、Nova Lite → Claude Haiku/Sonnet、max_tokens: 200）
  - セキュリティ（認証なし、HTTPS、API キー非露出）
  - ブラウザ対応（Chrome/Safari 最新版、レスポンシブ）
  - 可用性（オフライン対応、ローカルストレージ）
  - スケーラビリティ（サーバレス自動スケール、DynamoDB オンデマンド）
  - 保守性（マネージドサービス、IaC、可読性）

### ステップ 2: 実装に必要な追加事項の特定
- [x] 既存 NFR で不足している実装詳細を特定
- [x] 技術スタック選択に必要な追加情報を特定

### ステップ 3: NFR 要件計画の作成
- [x] チェックボックス付きの NFR 要件計画を生成
- [x] 実装に必要な追加事項のみに焦点を当てる
- [x] 各ステップにチェックボックス [] を付ける

### ステップ 4: コンテキストに適した質問の生成

**指示**: 既存の非機能要件を確認し、実装のために追加で必要な事項のみを質問します。重複した詳細化は避けます。

- [Answer]: タグ形式を使用して質問を埋め込む
- 実装に必要な技術選択や設定値に焦点を当てる
- **疑問がある場合は質問する** - 過信は悪いシステム品質につながる

**評価する質問カテゴリ**（必要な場合のみ）：
- **技術スタック選択** - フレームワーク、ライブラリ、AWS サービスの具体的な選択
- **パフォーマンス設定** - タイムアウト値、リトライ回数、キャッシュ戦略の具体化
- **コスト最適化** - Bedrock モデル選択、Lambda メモリ設定、DynamoDB 設定
- **セキュリティ実装** - CORS 設定、API Gateway 認証方式、環境変数管理
- **監視・ログ** - CloudWatch Logs の設定、エラー通知の方法

### ステップ 5: 計画の保存
- [ ] `aidlc-docs/construction/plans/nfr-requirements-plan.md` として保存
- [ ] ユーザー入力用のすべての [Answer]: タグを含める

### ステップ 6: ユーザー入力のリクエスト
- [ ] ユーザーに質問ファイル内の [Answer]: タグを直接記入するよう依頼
- [ ] 記入方法について明確な指示を提供

### ステップ 7: 回答の収集
- [ ] ユーザーが [Answer]: タグを使用してすべての質問に回答するまで待機
- [ ] すべての [Answer]: タグが完了するまで進まない

### ステップ 8: 回答の分析（必須）
進む前に、すべてのユーザー回答を以下の点で注意深く確認する必要があります：
- **曖昧または不明確な回答**: "mix of"、"somewhere between"、"not sure"、"depends"
- **未定義の基準または用語**: 明確な定義のない概念への参照
- **矛盾する回答**: 互いに矛盾する回答
- **実装詳細の欠落**: 特定のガイダンスが欠けている回答

### ステップ 9: 必須フォローアップ質問
ステップ 8 の分析で曖昧な回答が明らかになった場合、以下を行う必要があります：
- [Answer]: タグを使用して明確化質問ファイルを作成
- すべての曖昧さが完全に解決されるまで承認に進まない

### ステップ 10: NFR 要件成果物の生成
- [x] 以下を含む `aidlc-docs/construction/nfr-requirements/nfr-requirements.md` を作成：
  - 既存 NFR の参照（requirements.md へのリンク）
  - 実装に必要な追加 NFR 詳細
  - パフォーマンス目標の具体化
  - セキュリティ実装方針
  - 監視・ログ戦略
- [x] 以下を含む `aidlc-docs/construction/nfr-requirements/tech-stack-decisions.md` を作成：
  - フロントエンド技術スタック（React、Tailwind CSS、Context API）
  - バックエンド技術スタック（Lambda、API Gateway、DynamoDB）

  - インフラ技術スタック（AWS CDK、Amplify Hosting）
  - 開発ツール（TypeScript、ESLint、Prettier）

## 重要なルール

### 軽量化原則
- **既存 NFR を再利用**: requirements.md の内容を最大限活用
- **追加事項のみ定義**: 実装に必要な具体的な技術選択や設定値のみ
- **重複を避ける**: 既に定義されている内容を繰り返さない

### 計画フェーズのルール
- **コンテキストに適した質問**: 実装に必要な追加事項のみを尋ねる
- **必須回答分析**: 進む前に常に曖昧さの回答を分析
- **明示的承認が必要**: 生成開始前にユーザーが計画を承認する必要がある

### 生成フェーズのルール
- **計画に正確に従う**: ステップシーケンスから逸脱しない
- **チェックボックスを更新**: 各ステップ完了後すぐに [x] をマーク
- **完了を検証**: 次のステージに進む前にすべての成果物が完了していることを確認
