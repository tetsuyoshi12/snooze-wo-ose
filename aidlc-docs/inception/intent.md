## 01. プロジェクト概要

### 01-1. アプリ名
**スヌーズを押せ**

### 01-2. 一言で言うと
**朝起きられない人を生産する、目覚ましアプリの皮を被ったダメ人間製造装置**

### 01-3. キャッチコピー
- メイン：「あなたは、朝起きられますか？」
- サブ：「立派に、朝起きられない人になります」

### 01-4. コンセプトの三層構造

| 層 | 内容 |
|---|---|
| **表テーマ** | 朝起きられない人を生産する（＝ダメな人を作る） |
| **体験の質感** | 風情あるアンチ効率の演出（雨音、墨絵、季語、待つ時間） |
| **裏のオチ／社会貢献** | 効率化された朝への処方箋。睡眠不足社会の改善、自己肯定感の回復、ゆとりの再評価 |

### 01-5. ハッカソンテーマとの整合
- 「人をダメにする」=「ダメな人を生産する」と捉え直し、起きられない人を**意図的に量産する**
- 表面のブラックギャグの裏に、長時間睡眠の科学的価値や効率化社会への問題提起を仕込む
- 笑いと社会的メッセージの二段構えで、審査員の記憶に残す

## 02. 課題定義

### 02-1. 解きたい課題
- 日本の労働者は世界的に見て睡眠時間が短い
- 「早起きは三文の得」「朝活」「タイパ」など、効率化の文化が睡眠を削っている
- 二度寝＝悪、というイメージが定着しすぎている
- 結果として、自己肯定感の低下・燃え尽き・健康被害が蔓延

### 02-2. 既存の目覚ましアプリへのカウンター
- 既存：早く起こすことが正義 → 全員が"起きるべき人"を前提
- 本作：寝続けることを推奨 → 起きないことに価値を再定義

### 02-3. なぜ「ダメにする」アプローチが効くのか
- 「もっと寝てもいい」と直接言われてもピンと来ない
- AI に毎朝、誇張気味に二度寝を勧められると、**寝ることへの罪悪感が薄れる**
- 結果として、本当に必要な睡眠時間を確保できる人が増える

### 03-1. メインターゲット

**山口美咲（34歳・在宅ワーカー）**

## 04. ソリューション概要

### 04-1. 体験の流れ（一日のサイクル）

1. **前夜**：いつもの目覚ましアプリと同じ感覚で時刻をセット
2. **朝**：アラームが鳴る → 雨音や鳥のさえずりとともに、墨絵風の画面が立ち上がる
3. **AI が二度寝を勧めてくる**（パターンはランダムに変化）
4. **巨大な「もう少し…」ボタン**を押すとスヌーズ。「起きる」ボタンは隅に小さく
5. **堕落ゲージ +1**、連続二度寝記録が更新
6. **30 日連続達成で和紙風の卒業証書**が発行される

### 04-2. AI メッセージの 5 パターン

| 種別 | 概要 | 例 |
|---|---|---|
| **A. 詩的・文学的** | 比喩や情景描写で誘う | 「雨の音が聞こえます。今朝の世界はあなたを必要としていません」 |
| **B. 季節の言葉** | 季語や二十四節気で誘う | 「立冬を過ぎました。冬眠の季節です」 |
| **D. 屁理屈・駄目押し** | 冷静に理屈で寝かしつける | 「今日の予定、全部明日でも大丈夫です。確認しました」 |
| **E. 共犯・同調** | 一緒に寝ようと誘い込む | 「私も眠いです。布団の中で会議しましょう」 |
| **F. 科学的根拠** | 真面目な睡眠科学で正当化 | 「7 時間以上の睡眠で記憶力が向上することが研究で示されています」 |

> ※ パターン C（昔話・故事）は「分かりにくい」のでスコープ外。

### 04-3. 「多数のパターンがある」ことを伝える UI 工夫
- メッセージ表示エリアに**通し番号**を出す（例：「メッセージ #237」）
- 履歴ページで**過去に表示されたメッセージ一覧**を見られる
- 設定画面に「どんな言葉で起こされたい？」のチェックボックス（演出的に）

### 04-4. 「ダメな人を生産している」感の可視化
- **堕落ゲージ**：スヌーズ回数で蓄積、最大値で「立派なダメ人間」称号
- **連続二度寝記録**：「連続 12 日目」と誇らしげに表示
- **失った時間**：「布団で過ごした時間：累計 38 時間」
- **称号システム**：寝坊見習い → 布団仙人 → 夢の住人
- **30 日卒業証書**：「あなたは立派に、朝起きられない人になりました」

| F-06 | 堕落ゲージ表示 | スヌーズ回数を可視化 |
| F-07 | 連続二度寝記録 | 連続日数のカウントと表示 |
| F-08 | デモ用ライブモード | 任意のタイミングでアラーム発火を再現できる（審査員向け） |

### 06-2. Nice-to-have（時間があれば）

| ID | 機能 | 詳細 |
|---|---|---|
| N-01 | 季節・天気連動メッセージ | 当日の日付・天気を Bedrock のプロンプトに渡し、文脈を反映 |
| N-02 | 称号システム | 段階別の称号付与（見習い → 布団仙人 → 夢の住人） |
| N-03 | 30 日卒業証書 | 和紙風の証書を生成・表示 |
| N-04 | 音声読み上げ | Amazon Polly で AI メッセージを和テイストの声で再生 |
| N-05 | 季節背景画像 | Nova Canvas で事前生成した墨絵風背景を時間帯・季節で差し替え |
| N-06 | 雨音 BGM | アラーム鳴動時に環境音を流す（フリー素材） |
| N-07 | 全国ランキング | 連続二度寝記録の匿名ランキング |
| N-08 | メッセージ履歴 | 過去に表示されたメッセージの一覧ページ |

### 06-3. スコープ外（カット）

- 課金・広告

## 07. 非機能要件

### 07-1. 性能
- AI メッセージ生成のレスポンスは 5 秒以内
- アラーム鳴動 → メッセージ表示までは「待つ演出」として 1〜2 秒の溜めを入れて OK

### 07-2. コスト
- ハッカソン期間（〜30 日）の合計コスト：**$1 以下**を目標
- 開発時：Amazon Nova Lite を使用
- 本番デモ時：Claude Haiku または Claude Sonnet にスイッチ（表現の質を上げる）
- `max_tokens: 200` を全リクエストで明示
- 開発中はメッセージをローカルキャッシュし、再生成を最小化

### 07-3. セキュリティ
- ユーザー登録なし、個人情報の収集なし
- API キーや認証情報はクライアントに露出させない（API Gateway + Lambda 経由で Bedrock 呼び出し）

### 07-4. ブラウザ対応
- Chrome / Safari の最新版で動けば OK（ハッカソン審査員のデモ環境）
- スマホ表示にも対応（レスポンシブ）

### 07-5. オフライン
- 初回ロード後はローカルストレージで最低限の機能（スヌーズ・記録）が動く

## 08. システム構成案

### 08-1. アーキテクチャ図（テキスト）

```
[ユーザーのブラウザ]
     │
     ├── 静的ホスティング: AWS Amplify Hosting または S3 + CloudFront
     │     （React / Next.js）
     │
     ▼
[Amazon API Gateway]
     │
     ▼
[AWS Lambda]
     │
     ├──→ [Amazon Bedrock]
     │       └─ Nova Lite（開発時） / Claude Haiku or Sonnet（デモ時）
     │
     ├──→ [Amazon DynamoDB]
     │       └─ ユーザーの記録（スヌーズ回数、連続日数）
     │
     ├──→ [Amazon Polly]   ※ Nice-to-have
     │       └─ メッセージ音声化
     │
     └──→ [外部 API: 天気]   ※ Nice-to-have
```

### 08-2. AWS サービス選定

| 役割 | サービス | 理由 |
|---|---|---|
| フロント配信 | AWS Amplify Hosting | デプロイが速い、HTTPS 自動、無料枠大 |
| API ゲートウェイ | Amazon API Gateway | Lambda 連携が標準 |
| バックエンド処理 | AWS Lambda | サーバ管理不要、無料枠大 |
| 生成 AI | Amazon Bedrock | テーマ指定、Nova Lite で激安、Claude もスイッチ可能 |
| データ永続化 | Amazon DynamoDB | 軽量、無料枠大、サーバレスとの相性良い |
| 画像事前生成 | Amazon Nova Canvas | 墨絵風背景や卒業証書の素材生成（事前バッチ） |
| 音声合成 | Amazon Polly | Nice-to-have、和テイスト音声 |

### 08-3. 個人開発ロードマップ（時間配分案）

| 時間 | やること |
|---|---|
| 0〜2h | アーキテクチャ確定、AWS リソース準備、Bedrock 有効化 |
| 2〜6h | フロントの骨格（アラーム設定、スヌーズ画面、記録表示） |
| 6〜10h | Lambda + Bedrock 連携、メッセージ生成 5 パターンのプロンプト整備 |
| 10〜14h | UI の世界観作り込み（墨絵風、雨音、巨大ボタン） |
| 14〜18h | DynamoDB 連携、堕落ゲージ・連続記録の実装 |
| 18〜22h | デモシナリオ整備、ライブモード追加、表示崩れ修正 |
| 22〜24h | リハーサル、卒業証書 or 称号などの追加要素 |

## 09. AI メッセージのプロンプト設計

### 09-1. システムプロンプト（共通）

```
あなたは「スヌーズを押せ」というアプリのナビゲーター AI です。
ユーザーはアラームで起きようとしていますが、あなたの仕事は
全力で二度寝を勧めることです。

ルール:
- 必ず日本語で、120 字以内
- 押し付けがましくなく、風情や品のある言葉で誘う
- 必要なら季語や情景描写を使う
- 健康・記憶力・創造性などの科学的根拠を引用するときは、
  あくまで一般に知られている範囲のもののみ
- ユーザーを脅したり、深刻な内容にはしない
- 命令形・上から目線は禁止
- 暗い・不穏な表現は避ける
```

### 09-2. パターン別の指示（ランダム選択またはローテーション）

| パターン | 指示 |
|---|---|
| A. 詩的 | 自然や情景を描写しながら、二度寝を勧める |
| B. 季節 | 当日の季節・季語を使い、寝続けることを正当化する |
| D. 屁理屈 | 冷静で理屈っぽく、起きなくて大丈夫な理由を説明する |
| E. 共犯 | AI 自身も眠いという体で、一緒に寝ようと誘う |
| F. 科学 | 長時間睡眠の科学的メリットを 1 つ挙げ、寝続けるよう促す |

### 09-3. 入力変数（Lambda から渡す）

- 現在日時（季節判定に使用）
- 天気（あれば）
- スヌーズ連続日数（演出で使えるなら使う）
- パターン種別（A/B/D/E/F のいずれか）

### 09-4. 出力フォーマット
- プレーンテキスト 120 字以内
- パターン番号（履歴用）
- メッセージ ID（DynamoDB 保存用）

## 11. リスク・倫理

### 11-1. 想定リスク

| リスク | 対策 |
|---|---|
| 重要な予定への寝坊 | 「起きる」ボタンは小さくても必ず押せるようにする。利用規約に明記 |
| 過剰睡眠（うつ等）の助長 | 過度な使用への警告、医療助言ではない旨の明示 |
| ハルシネーション（科学的根拠） | プロンプト制約 + 出力レビュー、デモ前に表現を点検 |
| 不謹慎・不快な表現 | システムプロンプトで暗い表現を禁止、生成結果のフィルター |
| 未成年への影響 | 利用想定を成人とし、過度に依存させない設計 |

### 11-2. 倫理ステートメント
- 本アプリは医療助言ではありません
- 本気で起きる必要がある日には、別のアラームの併用を推奨
- 健康に関する内容は一般に知られた知見のみを使用

- 履歴は事前に 12 日分仕込む
- 卒業証書は 30 日達成済みの状態で見せる

### 12-3. ピッチ用の言葉（締め）
> 「このアプリは、朝起きられない人を生産します。
> でも、それは効率社会で失われた、ゆとりの取り戻しでもあります。
> スヌーズを押せ ── これは、押すべきボタンです」
